# 1.2 大图库浏览与检索展示

## 解决的问题

1.1 已修复目录接口的筛选与分页顺序，但网页仍用首次加载的 100 条目录数据匹配搜索命中。后端返回较早的 SKU 时，网页可能把它过滤掉。小程序虽然可以逐条请求商品详情，却产生每个命中一次请求的额外开销。

本轮把目录浏览页与搜索结果分开管理，搜索接口直接返回可展示的商品卡片，三端统一使用同一组后端数据。

## 接口变化

新增 `GET /api/catalog/page`，支持 `q`、`category`、`limit`、`offset`，默认每页 24 条，最大 200 条。返回：

```json
{
  "items": [],
  "total": 0,
  "offset": 0,
  "limit": 24,
  "next_offset": 0,
  "has_more": false
}
```

总数与列表共享同一筛选条件，只统计上架商品且至少包含一个已审核上架 SKU 的商品。旧 `/api/catalog/products` 数组接口保留。

`POST /api/search` 保留 `results`、`query_id`、耗时和版本字段，新增 `products`。卡片顺序与有效 SKU 排名一致，`selected_sku_id` 指向命中规格，卡片展示价使用该规格价格。商品与 SKU 批量读取，客户端无需逐命中访问商品详情；返回卡片不包含初始供货价格和人工定价字段。

前端 1.2 需要后端 1.2 的新增响应字段；旧客户端仍可继续使用已有接口。无需更改数据库结构或重建索引。

## 三端行为

- 网页和客户、商家小程序支持分类分页、总数提示和“加载更多”。小程序同时支持触底继续加载和下拉刷新。
- 分类切换重新请求服务端第一页；网页清除搜索后回到当前分类目录第一页，小程序清除时按既有行为重置分类。
- 网页直接渲染搜索返回的卡片，同时将其合并到对比功能所需的商品缓存中。首页未加载过的商品也能进入详情和规格对比。
- 翻页和检索请求使用局部请求序号，较早请求不能把结果追加到后来选中的分类。分页加载时禁用重复点击。
- 前端浏览逻辑提取到 `web/src/useDiscovery.ts`，减少主页面状态混用。
- 网页首页展示图使用运营配置或当前商品图片，不再写死演示图片 ID；网页与小程序商品列表对缺图规格显示占位提示。

## 验证

新增 3 个核心回归用例，累计 18 项通过：可见商品总数及分类分页；排名、命中 SKU 价格和非公开规格排除；105 个新商品之前的旧商品仍随检索响应返回。

另用独立数据库生成 126 商品、127 SKU，完成 6 项真实浏览器检查：

1. 初始 24 条，加载后 48 条，总数 126。
2. 分类在服务端筛选，游标重置，无更多数据时隐藏按钮。
3. 搜索命中首页前 100 条之外的商品，渲染阶段没有逐条详情请求。
4. 命中较贵 SKU 时，卡片、详情选中项和对比价均保持 98.76 元。
5. 清除搜索恢复第一页，390px 界面不横向溢出。
6. 连续切换分类时，最后一次选择生效。

浏览器检查没有 JavaScript 运行错误。Vue 类型检查与生产构建通过；两个原生小程序由共享源码重新生成并检查 JavaScript 语法，微信开发者工具及真机验收仍待外部环境，不能以浏览器结果代替。

## 复现与范围

核心用例：`python -m pytest -q`。前端：`npm --prefix web run build`。原生项目：`python -m scripts.build_miniapps`。

浏览器脚本为 `scripts/browser_discovery_check.py`。设置指向全新临时目录的 `DATA_DIR` 和 `DATABASE_URL` 后执行 `--prepare`，使用相同环境启动后端，再执行 `--base-url http://127.0.0.1:8012`。需要 Playwright 及 Edge；脚本拒绝向已有账户的数据库写入测试样本，凭证只写入该临时目录。测试证据保留在本地 `local-only/`。

本轮不改检索模型和采购优化算法，不重新宣称检索精度提升。1.0 课程报告和 1.1 记录保留为历史快照。仓库继续 MIT 开源，课程原件、运行数据、图片与账号配置不上传。
