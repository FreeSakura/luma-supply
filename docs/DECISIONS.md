# 需求与设计决定

| 编号 | 决定 | 原因及影响 |
|---|---|---|
| D01 | 题目为灯具商城，分类采用灯具分类 | 原 PDF 家具字样视为模板遗留 |
| D02 | 客服创建订单，客户确认配送信息 | 保留原始成交模式，不引入在线支付替代 |
| D03 | 展示价 = min(初始价, 已审核有效供货价) × 定价乘数，向整数分四舍五入；SKU 人工价优先 | 乘数按原图直接相乘，不解释为加成率；规则版本化；订单金额独立快照 |
| D04 | 报价新版本待审期间保留旧批准版本；新版本通过后旧版失效 | 保留连续供货与历史追溯；下架立即生效，上架重新审核 |
| D05 | 未知库存允许展示并注明待确认，采购优化排除未知数量 | 不将有货状态等同无限库存 |
| D06 | 采购同一 SKU 行不拆给多个商家；运费按启用商家收取一次 | 构成带固定启用费用的离散优化问题 |
| D07 | Vue 3 + 原生微信小程序 + FastAPI + SQLAlchemy | 方案技术栈为建议；现有 Python 环境利于算法复现，业务采用模块化单体，算法可独立部署 |
| D08 | SQLite 为零配置课程运行模式，MySQL 通过数据库 URL 配置 | 事务、外键、唯一键为业务正确性基础；MySQL 需另行实机验证 |
| D09 | 阿里云、微信 OAuth、短信使用真实适配器并暴露配置状态 | 没有账号时返回未配置，开发验证码仅本地开发模式；禁止伪称接通 |
| D10 | 实验使用明示来源数据，合成数据仅证明实现与受控条件效果 | 独立真实场景图及授权依赖必须单列，不将同图变换当真实效果 |
| D11 | 仓库私有，课程原件及报告仅本地 | 用户明确选择，后续开源需要单独审查数据与授权 |

成员姓名和实际分工未提供，不虚构小组成员贡献或按周开发经历；迭代按真实提交顺序记录。

## 1.1 开源决定

用户在本地交付后明确要求将 GitHub 仓库开源。本版本采用 MIT 许可证并将可见性改为 public，替代 D11 的私有可见性决定。其余本地数据、凭证及原件排除规则继续执行。
