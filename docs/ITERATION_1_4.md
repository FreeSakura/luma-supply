# 1.4 询价协同与可靠转单

## 业务变化

1.3 已保存结构化需求及参考快照，本轮补齐询价提交之后的协作：客户补充问题、客服回复、客户撤回、客服带原因关闭、只读历史和关联订单入口。沟通记录不改写原始商品与金额快照。

询价状态仍使用原字段，扩展为：

| 当前状态 | 可执行操作 | 后续状态 |
|---|---|---|
| open | 客户补充、客服回复 | open |
| open | 所属客户填写原因撤回 | withdrawn |
| open | 有订单权限的客服填写原因关闭 | closed |
| open | 客服创建销售订单 | ordered |
| withdrawn / closed / ordered | 查看原需求和历史，已转单可打开关联订单 | 不再追加消息或转单 |

需要改选商品时，从清单重新询价，不把已结束记录悄悄改回处理中。撤回、关闭和转单没有物理删除旧需求。

## 接口

- `GET /api/inquiries?status=open`：新增可选状态筛选；数组响应兼容原客户端。
- `GET /api/inquiries/{id}`：需求、参考快照和时间顺序的处理记录。
- `POST /api/inquiries/{id}/messages`：客户补充或客服回复。
- `POST /api/inquiries/{id}/withdraw`：所属客户撤回。
- `POST /api/inquiries/{id}/close`：订单模块员工或管理员关闭。

三个写接口均使用 `{"message":"具体内容或原因"}`，去除前后空白后必须非空，最长 2000 字符。未结束询价才可写入。处理记录保存操作人名称与角色快照、动作、内容和 UTC 时间；内部账号 ID 不返回给客户。

客户只能查看和操作自己的询价，商家及无订单权限的员工不能访问。客户补充、客服回复和结束处理使用已有站内通知；未接入短信、邮件或外部即时通信。

## 数据与事务

新增 `inquiry_events` 表及按询价 ID 查询的索引。服务启动创建新增表，不改变已有表列；旧询价没有历史事件时保持空历史，界面仍显示原需求，不伪造过去的处理记录。SQL 导出更新至 26 张表。

消息、撤回、关闭通过条件更新校验询价仍为 open 且没有关联订单。转单使用同样的状态条件，在同一数据库事务中绑定询价与销售订单。两个不同幂等键同时转换同一询价时，仅一个成功，失败请求的订单、明细和采购草稿全部回滚。

询价 HTTP 接口从运营模块提取到 `backend/inquiries.py`，规则与快照辅助函数仍在 `backend/inquiry_service.py`。

## 响应发送前提交

联调发现登录响应返回后立即读取，可能遇到会话事务尚未提交的窗口。已将全部数据库依赖显式设置为 `Depends(session, scope="function")`，在处理函数返回后、HTTP 响应发送前完成提交或回滚。

这符合 [FastAPI 的 yield 依赖生命周期说明](https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/#early-exit-and-scope)。文件响应仅使用处理函数已经取得的文件路径，发送文件时不依赖打开的数据库会话。

增加提交阶段唯一键冲突用例，验证客户端收到 409，而不是携带未持久化令牌的 200 响应。没有通过延时、轮询重试或放宽权限掩盖此问题。

## 验证范围

核心测试累计 27 项。本轮覆盖：

1. 客户与客服消息顺序、通知及原快照保持不变。
2. 对象归属及角色限制，空消息被拒绝。
3. 撤回/关闭后拒绝继续沟通和转单，失败事务不留下订单。
4. 旧询价空历史兼容读取。
5. 两个真实并发请求转换同一询价，结果为一次 201、一次 409，数据库只留一套订单记录。
6. 提交失败不会被误报为成功。

独立测试库的 6 项浏览器检查通过，包括客户补充、客服回复与关闭、客户撤回和筛选、转单记录及关联订单、390px 历史详情；没有 JavaScript 运行错误。测试在退出界面完成后切换账号，没有使用任意等待时间绕过状态问题。

Vue 构建通过。原生客户小程序提供查看沟通、补充、撤回、筛选和关联订单入口，共享代码同步生成商家项目；商家依旧没有询价访问权限。原生 JavaScript 已检查，微信真机未作为已验收项目。数据库并发验证使用 SQLite，MySQL 的目标部署验证仍待完成。

## 升级

1. 使用已有备份脚本保存当前数据库与附件。
2. 安装锁定依赖，构建前端，重启 1.4 后端以创建事件表及索引。
3. 使用匹配版本的网页与原生小程序源码。

历史课程报告保留为旧版本快照，本轮不改检索模型、不重跑算法精度实验，也不改变既有付款与履约边界。
