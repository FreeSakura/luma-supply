# 1.7 房间清单编辑与可靠询价预览

## 本轮变化

原网页直接修改清单行的数量和备注，再调用保存接口；保存失败时，页面金额可能仍按未保存的数量显示。本轮改为独立编辑草稿，保存成功后用服务端返回值替换该行，保留其他商品的勾选状态。取消或保存失败不会改写已确认的清单金额，失败草稿留在弹窗供修改或重试。

编辑入口支持房间、数量、备注、价格关注与供货关注。房间可输入新名称或选择已有名称；移动时保留清单项 ID。目标房间已有相同 SKU 时明确提示冲突，不自动合并数量、不覆盖已有备注。原生客户小程序同步该流程，共享源码也同步生成商家项目，商家仍无客户清单访问权限。

询价预览增加响应有效性检查：预览请求期间修改预算等需求后，旧响应不会重新显示为可提交预览，用户需要按当前需求再预览。正式提交期间锁定输入和关闭操作，避免修改提交中的表单。服务端仍在提交时重新读取价格和可售状态。

## 新增接口

`PATCH /api/wishlist/{wish_id}` 仅允许所属客户修改，接受：

```json
{
  "room": "书房",
  "quantity": 4,
  "note": "靠窗阅读区，保留安装空间",
  "watch_price": true,
  "watch_stock": true
}
```

字段可单独提交，未提交的字段保留原值。房间首尾空格去除后必须非空，最长 60 字符；数量为 1–100000 的整数；备注最长 300 字符。响应包含更新后的清单项、当前 SKU 展示信息与商品名称。

- 越权修改返回 403；同客户、同 SKU、同房间冲突返回 409。
- 原增加清单和删除接口保留；创建清单同样规范化房间名称。
- 已下架商品仍可整理其清单备注或移除，但不能绕过询价可售检查。
- 已提交询价的房间、数量、备注、价格快照不受后续清单编辑影响。
- 无数据库结构变更；本轮未新增跨设备编辑版本，多个设备同时编辑同项仍按最后成功写入处理。

## 验证范围

核心测试累计 33 项。新增三项检查覆盖：保留 ID 的移动与部分修改、未提交字段保留、历史询价快照不变；客户归属与角色限制、目标房间冲突且两项数据都保留；无效数量/空白房间/超长备注拒绝、下架商品整理与询价限制。

`scripts/browser_wishlist_check.py` 使用独立演示数据库，完成六项场景：

1. 取消编辑保持已保存数量与已选金额。
2. 同规格房间冲突显示错误并保留草稿。
3. 保存房间、数量、备注后更新金额，保留其他勾选。
4. 注入一次 503 保存失败，确认页面未显示未保存金额。
5. 390px 编辑弹窗无横向溢出；延迟返回的旧预览不能启用提交。
6. 重新预览并提交后，详情显示已保存的房间、数量和备注快照。

`scripts/check_miniapp_wishlist.cjs` 检查两个生成项目共享页面逻辑的失败草稿保留、PATCH 请求及旧预览丢弃；已纳入 CI。原生源码执行检查不代表微信开发者工具或真机验收，MySQL 与外部平台验证范围未扩大。

## 升级与本地产物

1.7.0 前后端需要成套更新，新增编辑入口依赖 PATCH 接口。构建 `web`，运行 `python scripts/build_miniapps.py` 生成两个原生项目；无需数据库迁移。桌面与手机截图、浏览器结果、核心测试记录、说明与源码包保存在本地 `output/iteration-1.7/`，不随公开仓库推送。原课程报告保留为历史交付快照。
