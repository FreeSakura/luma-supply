# 1.1 搜索正确性与采购基线迭代

## 商品筛选先于分页

原实现先截取最近 100 条商品，再在 Python 中匹配关键字。商品增加后，较早的商品即使 SKU 完全匹配也无法命中。

现在在数据库中对商品名、标题以及已上架 SKU 的编码、颜色、规格做筛选，再按商品 ID 降序分页。关联条件采用 EXISTS，多个匹配规格不会把同一商品重复分页。`%` 和 `_` 按普通用户字符处理，避免 SKU 搜索意外匹配整个库。

接口保持列表响应，新增 `offset`（默认 0）。`limit` 范围为 1—200，非法分页参数返回 422。详情仍默认选中命中规格，列表价格取该规格价格。商品列表只批量读取当前页的 SKU，不再读取全表；单个详情只读取所属商品规格。

验证用例在旧商品之后新增 105 个商品，证明旧 SKU 仍被检索到，并检查分页连续性、字面通配符、未审核规格排除和命中价格。

## 检索元数据刷新

向量与图片相关，商品标题、规格与价格则属于实时业务数据。原实现即使刷新名称和类别，TF-IDF 重排仍使用索引中的旧文本。

现在共享 `sku_search_entry` 构造文本，在查询时批量读取当前 SKU/SPU，更新文本、编码、名称、属性和价格。图片已从 SKU 移除时，对应旧向量候选立即排除；保留下来的候选保持原向量行位置。商品状态仍在业务返回阶段过滤。

回归验证覆盖文本更新、移除图片与向量位置对应。30 个索引视图的刷新只执行 3 次 SELECT（商品规格、有效报价、定价规则），避免逐视图查询。

本轮不改变图像编码器与融合权重，也不重新宣称真实照片准确率。历史离线实验继续作为 1.0 数据快照保留。

## 增量运费基线

同一商家的运费按订单中所选报价的最大适用运费收一次。原增量贪心对已经选过的商家一律认为新增运费为零。

现在记录每个商家已计入的运费，并使用：

`新增成本 = 本行数量 × 单价 + max(0, 当前报价运费 - 该商家已计运费)`。

反例：第一行选择商家 A，商品 10 分、运费 10 分；第二行 A 商品 10 分、运费 100 分，B 商品 20 分、运费 10 分。旧基线误选 A，总计 120 分；修正后选 B，总计 50 分，与枚举结果一致。CP-SAT 的目标函数本身正确，本轮未修改其模型。
