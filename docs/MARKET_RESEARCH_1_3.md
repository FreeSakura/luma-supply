# 灯具商城竞品案头调研与 1.3 产品取舍

调研日期：2026-09-27。对象为公开网站和官方帮助内容，覆盖灯具零售、项目选品和 B2B 询价。没有访谈用户、购买商品或进入商家付费后台，也没有取得可比销量与转化数据。因此本报告属于产品能力案头调研，不给出市场规模、份额或收益提升的虚构结论。

## 观察与证据

| 对象 | 公开资料中的做法 | 可借鉴的优点 | 本项目适用边界 |
|---|---|---|---|
| Lumens | 灯具导航按类型和房间组织；提供 Kelvin 色温说明 | 在选品时解释参数与空间使用的关系，降低只按外观决策的风险 | 学习导购方式，不复制房间照度承诺或把温度区间当强制标准 |
| Lamps Plus | LED 导购区别功率、流明、显色和色温，使用易懂说明 | 把消费者容易混淆的参数拆开，便于进行规格比较 | 提示 K 是光色、W 是耗电功率、lm 用于比较光通量；缺失数据明确提示 |
| Ferguson Home / Build | 官方页面建议用 Project Tool 保存选品并按项目或房间组织，向顾问分享选择 | 选品清单能承接后续咨询，而不只是收藏夹 | 在已有 room / SKU 清单上增加分组、选择和金额汇总，保留平台客服成交 |
| Alibaba.com | 官方 RFQ 说明允许买家描述具体采购需求，再由供应商回应；官方搜索指南提供图搜与 RFQ 路径 | 找货和表达采购需求形成连续流程，需求越明确越容易比较报价内容 | 形成平台内结构化询价；不照搬开放供应商竞标或声称接入其平台 |

本次直接打开部分页面遇到 403 或超时；相关观察来自搜索工具返回的官方页面正文摘录，不声称完成了这些站点的登录态交互体验。Lumens 导购页的正文及导航可直接读取。下面的来源可供复核，产品功能以后可能改变。

## 官方来源

1. [Lumens — Understanding Kelvin Color Temperature](https://the-edit.lumens.com/the-guides/understanding-kelvin-color-temperature/)。阅读其导航与色温解释，不将页面建议作为工程规范。
2. [Lamps Plus — How to Buy LED Lighting](https://www.lampsplus.com/ideas-and-advice/how-to-buy-led-lighting/)。官方检索正文明确区别流明与瓦数。
3. [Lamps Plus — LED and Color Temperature Explained](https://www.lampsplus.com/ideas-and-advice/led-color-temperature-explained/)。不同导购对暖白等名称划分并不完全一致，所以本项目保留实际 K 数值。
4. [Ferguson Home / Build — Jackson Selection Center](https://www.build.com/showroom/branch/jackson-tn-selection-center-0178)。官方页面的 Projects 段落说明按项目或房间保存及分享选择。只据此确认这项能力，不推断其完整预算系统。
5. [Alibaba Seller Central — What is the Request for Quotation tool](https://seller.alibaba.com/learningcenter/content/detail/PX2U9ID5.htm)。公开 RFQ 教程。
6. [Alibaba.com Team — How to Search for Products](https://reads.alibaba.com/how-to-search-for-products-on-alibaba-com/)。官方搜索资料中的图像检索和 RFQ 路径。

## 当前项目的具体缺口

1. SKU 已存 `cct_k` 等参数，但首页不能按色温筛选；对比界面大量显示字段代码，缺少参数含义。
2. 选购清单已经有房间和数量，却平铺显示；没有房间汇总与勾选，点击询价会提交全部清单。
3. 询价只保留 SKU ID、数量、房间、备注，缺少项目名、预算、期望到货日期和替代品偏好。客服列表不易直接理解客户需求。
4. 商品变更后，仅凭旧 SKU ID 很难还原询价时看到的名称、规格和参考价。

这些是代码观察。它们是否显著影响转化，需要后续真实用户验证，不能由竞品有某个功能直接推出。

## 本轮选择

| 改进 | 对业务的作用 | 实现代价 | 决定 |
|---|---|---|---|
| 实际色温筛选与参数释义 | 帮助选中正确规格，参数缺失不猜测 | 小，复用 SKU 属性与检索过滤 | 1.3 实现 |
| 按房间勾选与金额汇总 | 可只咨询一个房间，查看合计数量和参考金额 | 中，复用 Wishlist | 1.3 实现 |
| 询价预览与结构化需求 | 将预算、期望日期、目的地和替代偏好交给客服 | 中，新增关联需求表 | 1.3 实现 |
| 提交快照 | 商品后续变更不覆盖已发送的参考信息 | 小，复用 JSON 明细 | 1.3 实现 |
| 自动照明设计、AR、开放多商家竞标 | 需要真实资料、模型或新的交易机制 | 大且存在数据依赖 | 本轮不做 |

## 设计原则

- 以实际已审核 SKU 的 K 数值作为筛选项，不根据图片推测参数，不自动判定某灯适合所有同类房间。
- 房间汇总和预算差额均为人民币整数分计算，只含商品参考金额，不含运费与安装；超过预算提示后仍可询价，便于客服协商。
- 期望到货日期是客户需求，不是商家交付承诺。允许替代品是咨询偏好，不直接修改订单或自动购买替代品。
- 预览只读取数据；提交时重新校验归属、上架状态和当前价格，保存快照。客户只能看到自己的询价，商家不能越权读取客户需求。
- 只借鉴交互原则，不复制竞品图片、商标、页面代码或宣传数据。保留本项目客服协助成交的流程。

## 后续验证方法

先验证正确性：色温过滤和命中 SKU 一致；只提交已选择的房间条目；单位价格乘数量与汇总一致；商品改价后询价快照不变；客服可以据询价建立订单。

再做人工可用性研究：邀请目标用户完成“为两个房间选择灯具，只对其中一个房间询价”的任务，记录任务完成率、漏填需求项、发起询价前操作次数及需要客服追问的内容。没有做这项研究前，不报告转化率或沟通成本提升百分比。
