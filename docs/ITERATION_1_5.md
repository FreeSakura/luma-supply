# 1.5 三端界面与操作效率升级

## 交互变化

| 端 | 界面调整 | 操作变化 |
|---|---|---|
| 管理端 | 深绿分组导航、暖白内容区、清晰的数据卡片与表格 | 当前列表关键词搜索、状态筛选、舒适/紧凑密度切换；Ctrl/Cmd + K 按权限查找工作区 |
| 客户端 | 有边界的选灯主视觉、更清楚的规格和价格层级、明确的商品操作 | 卡片直接选规格、加入对比；手机底部带文字的发现/清单/询价/订单/资料导航 |
| 商家端 | 独立供货工作台、本人报价待办统计、商品资料入口 | 点击待审核/需修改/已到期数字进入对应列表；商品卡片直接发起报价 |

网页三角色共用基础视觉规范，保留客户浏览与后台管理各自的信息密度。移动端采用抽屉导航和完整内容宽度，表格在容器内横向滚动。字号、间距、按钮尺寸、弹窗及状态颜色同步调整。

两个原生微信小程序的共享样式拆成基础层和主题层，生成时一并同步。首页增加角色快捷入口，商家待办使用自己的实际报价数据；工作列表增加关键词和报价状态过滤；个人资料增加账号信息区；底部原生标签随角色和语言切换。未引入新 UI 依赖。

## 规则与可访问性

- 列表筛选只处理当前角色已获授权的数据，不增加后端读取范围。切换工作区会清空该列表筛选；紧凑偏好保存在浏览器本地。
- 商家统计展示其报价版本记录，不把待审核版本当成生效供货价。已删除、已下架、已到期状态优先展示；实际报价审核和价格计算仍由业务接口决定。
- 弹窗支持 Esc 关闭、Tab/Shift+Tab 焦点循环和关闭后焦点返回。手机抽屉关闭时从可见区域及键盘访问中移除。
- 快速跳转只包含当前账号可访问页面；列表加载显示进度，筛选无结果提供调整关键词/清除条件提示。
- 本轮不宣称转化率、操作耗时或商业收益提升；尚未开展真实用户可用性研究。

## 验证与证据

`scripts/browser_ui_check.py` 在独立 SQLite 测试库生成 126 商品、127 SKU、三角色、四种报价状态和两笔订单。图片使用项目已有原创程序图，不是商家实拍。

浏览器检查覆盖：

1. 商品卡片选规格，弹窗焦点循环、Esc 和焦点恢复。
2. Ctrl + K 查找工作区并用 Enter 跳转。
3. 客户手机底部导航、订单入口与无页面横向溢出。
4. 商家待办直接进入本人被驳回/已到期报价。
5. 商家从商品卡片提交供货报价。
6. 管理端订单关键词、状态和紧凑密度切换。
7. 管理端手机抽屉打开/关闭及总览布局。

桌面 1440 × 1000 与手机视口 390 × 844 的三角色截图、检查结果存入本地交付目录。截图展示演示数据。27 项核心业务测试、Vue 类型检查与生产构建、原生共享 JavaScript 语法检查作为回归范围。

原生小程序本轮完成源码与语法检查；尚未使用微信开发者工具、真机或真实 AppID 验证，不把浏览器手机视口当作微信真机验收。

## 升级与兼容

版本为 1.5.0，没有数据库结构或业务 API 变更。执行 `npm ci` 和 `npm run build`（`web` 目录），服务使用新生成的 `web/dist`；已打开页面需刷新。后端版本元信息更新需要在正常部署窗口重启服务。

编辑原生应用时以 `miniapps/shared` 为源，运行 `python scripts/build_miniapps.py` 后分别导入客户与商家项目。已有外部服务联调项和算法验证边界不变，历史课程报告作为原交付快照保留，本轮说明随源码和本地交付归档。
