# 2.1 安全与性能迭代

日期：2026-10-09。基线：2.0 / 30198dd。2.1集中改进认证并发、管理会话、文件与检索权限、客户端恢复、列表效率及备份完整性。

## 改动

- TOTP支持RFC6238，记录已使用时间步防重放。生产管理员使用个人密钥；管理会话闲置30分钟失效，敏感操作要求15分钟内身份验证。
- 账户和来源限速使用数据库计数，账户别名统一到用户ID。验证码按摘要、期限和尝试数条件消费。
- 清单及询价保持版本和幂等规则；网页及小程序按账户保存草稿和待处理请求，多个提交意图独立完成。
- 图片按EXIF转正，MP4核验容器及视频轨；未发布图片不能用作其他用户的检索输入。
- 商家新增SKU校验商品归属，售后状态及历史使用条件更新。
- 目录只预取相关规格报价；订单分页、服务端搜索和关系批量读取；新增报价、订单和通知索引。
- 索引采用跨进程发布锁及独立临时文件；不可读索引返回503，普通目录继续服务。
- 备份增加完成标记和SHA256清单，关闭连接后计算校验；恢复预检、更新媒体路径、撤销会话并重建索引。
- 错误响应包含code、message、detail和request_id。启动脚本检查迁移及构建时间。

60项pytest通过，Vue类型检查与构建通过；十个Edge浏览器检查通过，包含页面重载后的询价重试和管理重新验证；四组小程序检查及网页提交标识检查通过。恢复副本验证账号、订单、图片及访问控制。

L0：100 SPU、300 SKU、1200张图、10家商家、3000条报价、1000张订单、3000行明细。服务进程固定4个逻辑CPU，每场景每轮预热20次，测量1000次，独立3轮，共9000次测量，错误数0。

## 升级

先备份，运行 `python -m backend.migrations`。2.1增加totp_uses及sessions的last_seen_at、authenticated_at、mfa_verified，同时创建查询索引。网页重新构建，小程序重新生成。

管理MFA配置：`python -m scripts.configure_mfa --user admin --output local-only/security/mfa.json`，将MFA_SECRETS_FILE指向该文件；管理员保管密钥，轮换时使用--rotate。

订单列表增加limit、offset，默认最多100条，两端以50条分页。原有响应类型、清单version和询价submission_key保持兼容。恢复副本中的旧会话统一撤销。
